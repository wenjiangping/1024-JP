# Go Lita

> 一场为冬天多攒一点的小冒险：2D 横屏、4:3、单人森林积分跑酷
>
> 游戏设定 v 0.1.4｜2026-10-24｜本地审阅稿
>
> 本版将主题从设计师创作改为 Lita 的森林采集，承接 Lita 系列教程的“森林储藏计划”。

## 1. 游戏定位

| 项目 | 本版设定 |
|---|---|
| 游戏名称 | **Go Lita** |
| XBuilder 项目 | 沿用现有项目标识 `IdeaDash`；游戏内显示英文名 Go Lita |
| 主人公 | XBuilder 默认松鼠角色 Lita，优先使用平台现成资源 |
| 游戏类型 | 2D 横向自动跑酷、收集与积分挑战 |
| 玩家人数 | 单人 |
| 画面比例 | 横屏 4:3；具体舞台像素尺寸在项目中确认 |
| 场景范围 | 一片连续的森林小径，一套场景，不制作多关卡 |
| 核心操作 | Lita 自动奔跑，玩家只负责单次跳跃 |
| 单局目标 | 跳过林间障碍、收集松果和安全蘑菇，攒更多囤粮分 |
| 体验方向 | 容易上手、轻松耐玩，挑战随着时间缓慢增加 |
| 美术方向 | 明亮清新的扁平卡通插图，轮廓清楚、细节克制 |

核心体验：**看准小径上的障碍，轻轻一跳，顺手收下食物，帮助 Lita 把这一趟森林采集跑得更远。**

**Go Lita** 像一句“出发吧，Lita！”，简短、活泼，表达玩家对 Lita 森林冒险的鼓励。松果与蘑菇共同构成这次采集目标。

## 2. 世界观与故事

### 一句话故事

冬天快到了，Lita 沿着熟悉的森林小径出发，把一路遇见的松果和蘑菇攒成过冬的底气；每多跑一段，都可能带来新的收获。

### 故事背景

森林的树叶开始泛黄，清晨的风也渐渐凉了。Lita 正为过冬准备食物：今天的小径上有掉落的松果，也有已经成熟、可以安全采集的蘑菇。

这些好东西可不会整整齐齐地摆在一起。树桩挡住了去路，圆石横在脚边，风吹落的树枝也需要跨过去。Lita 决定轻装出发，一边跑、一边观察，跳过障碍，把沿路的收获记进这一次采集。

游戏不安排追赶 Lita 的敌人，也没有必须在倒计时内完成的任务。玩家是在帮 Lita 积累收获，逐步掌握森林里的奔跑节奏。

> 再往前跑一点，冬天就多安心一点。

碰到障碍意味着这一趟采集暂时停下。结束页展示本局收获与称号，玩家可以马上再出发。本局分数会重置，不设置跨局库存、物资丢失或连续签到系统。

### 与 Lita 教程故事的关系

本游戏取自附件故事线中的“森林探索与采集”片段，作为独立的小冒险：

- 延续 Lita、森林、松果、蘑菇和准备过冬的基本背景。
- 将教程中的观察、选择路线与记录收获，转化为看障碍、决定跳跃时机和收集计分。
- 本次只做森林小径；河道、小船、储藏区、分类归篮不属于本版玩法。
- Nico 和 Bala 不进入本版核心循环，不增加对手、追逐或协作机制。
- 角色称谓统一使用 Lita，不额外补设性别或与跑酷无关的身世。

附件提供故事背景；十个教程单元的知识点与任务流程不作为本跑酷游戏的制作清单。

## 3. 主角与现成资源复用

直接使用用户项目中的默认松鼠 Lita。角色的外形、配色和识别特征以实际资源为准，不另外设计成人类设计师，也不为换主题重新制作整套主角。

| 状态 | 计划表现 | 最小实现方式 |
|---|---|---|
| 待机 | 主菜单中准备出发的 Lita | 优先选现成待机造型；缺少时用合适的静态造型 |
| 跑步 | 面向右侧的小跑循环 | 检查现成动画；不足时先用现成造型搭配简单运动表现 |
| 跳跃 | Lita 起跳、腾空、落地 | 优先复用现成姿势，由位移表现跳跃；不预设已有专用跳跃动画 |
| 受阻/结束 | Lita 停下，采集暂告一段落 | 可暂停当前造型并显示轻微受阻反馈；不强制补死亡动画 |

角色始终保持易辨认的大小。松鼠尾巴较大，碰撞体验应以身体和脚部为重点；正式实现时需验证 SPX 的碰撞设置，避免仅因蓬松尾巴或透明边缘碰到障碍就结束。

当前文档只确定复用方向。Lita 的现成造型数量、动画名称、默认朝向和素材尺寸均需在项目中核实，不作为已确认能力。

## 4. 森林场景与游戏对象

### 一张森林小径

画面结构参考用户提供的横版跑酷截图：上方为天空和云朵，中景为层叠树林或远山，下方是一条水平、连续的林间草地小径。

- Lita 位于画面左侧约四分之一处附近，朝右奔跑。
- 障碍和收集物从右向左移动，形成持续前进的感觉。
- 地面保持平整，草地边缘可以有简单土层；不做悬崖、落坑、斜坡或移动平台。
- 树木、灌木、花草主要放在背景，减少与危险对象相似的前景装饰。
- MVP 先用一张静态森林背景和一条可复用地面；视差滚动作为有余力时的补充。

这是同一片森林的持续跑酷，不以换背景、走到终点或完成章节推动进程。

### 障碍物

三种外观共用同一类地面障碍规则，控制在相近、可轻松跳过的尺寸。它们用于丰富森林观感，不增加三套不同操作。

| 障碍 | 外观与识别 | 玩法规则 |
|---|---|---|
| 挡路小树桩 | 低矮树桩、清楚的切面与根部，色块轮廓简洁 | 从右侧进入，单次跳跃可越过；碰撞结束本局 |
| 路中圆石 | 一块圆润的灰蓝色石头，与草地有清楚色差 | 与树桩使用同一移动和碰撞规则 |
| 落枝堆 | 几根短树枝交叠成紧凑低矮的一堆，不向远处伸出细长尖枝 | 与树桩使用同一移动和碰撞规则 |

所有障碍只在地面出现。参考截图中的尖刺、头顶陷阱和复杂障碍组合不纳入本版。装饰性树桩、石头或枝条也不要放在跑道上，以免玩家分不清哪些会碰撞。

### 收集物

| 收集物 | 出现方式 | 奖励 | 故事含义 |
|---|---|---:|---|
| 松果 | 较常见，出现在安全的地面附近或容易够到的低弧线上 | +50 囤粮分 | 最熟悉的过冬收获 |
| 成熟的安全蘑菇 | 较少见，使用统一、清楚的可收集外观 | +100 囤粮分 | 路途中额外找到的好食物 |

蘑菇在本版中全部为成熟、安全的目标，不引入毒性、等待成熟或食物变质。玩家只需识别“能收集的食物”和“需要跳过的障碍”。

收集物与障碍不重叠、不藏在障碍背后；可以顺路收集，也可以放弃，漏捡不会扣分。松果和蘑菇只加分，不触发攻击、冲刺、护盾或复杂技能。

## 5. 核心玩法与操作

### 单局循环

1. 主菜单显示 Lita 和森林小径，点击“出发囤粮”开始。
2. 前几秒提供安全起步，Lita 自动跑动，玩家可以试跳并收集食物。
3. 低矮障碍逐步出现，玩家看准时机跳过，沿途积累囤粮分。
4. 分数达到门槛时出现简短称号提示；游戏仍在同一个森林场景中继续。
5. 玩家可暂停、继续，或直接重新开始。
6. 碰到障碍后，本局结束，查看囤粮分、收集数量和本局称号，再选择重试或返回主菜单。

### 操作规则

- 跳跃：按空格键、上方向键，或点击游戏区域。
- 单次跳跃：只有落地后才能再次起跳；长按不自动连跳。
- Lita 自动奔跑，不需要按住前进键；没有左右移动、下蹲、攻击和二段跳。
- 暂停和菜单按钮的点击单独处理，不同时触发跳跃。
- 开始、继续和重试的触发输入只处理一次，不让同一次按键或点击在切换状态后又触发额外动作。

### 结束与重置

本版沿用“碰到障碍结束”的简单规则，不增加生命条。通过宽松的跳跃窗口、较慢的初速和充足空档提升耐玩度。

暂停时冻结计分、难度计时、生成计时和场景对象；恢复后从暂停前的状态继续。重试时清空旧对象、当前分数、收集数量和加速状态，重新给予安全起步时间。

## 6. 囤粮分、成长称号与难度

### 囤粮分

计分名称从“脑洞值”改为更符合松鼠采集主题的“囤粮分”。

- 每有效奔跑 1 秒：增加 10 囤粮分。
- 每收集 1 颗松果：增加 50 囤粮分。
- 每收集 1 个安全蘑菇：增加 100 囤粮分。
- 本局囤粮分 = 有效奔跑整秒数 × 10 + 松果数量 × 50 + 蘑菇数量 × 100。

时间项奖励持续探索，不等同于获得食物；结算时将总分与实际食物数量分别显示。主菜单、说明、暂停和结束状态不累计时间分，计分按时间计算而不是按动画帧数计算。

### 有趣的成长称号

保留“分数增长时获得称号”的体验，把职场称号换成森林探索中的小成就。称号描述 Lita 的行动、路线和探险表现，不绑定某一种收集物。

| 囤粮分建议区间 | 称号 | 游戏中的含义 |
|---:|---|---|
| 0–199 | 蹦跶小新手 | 刚进入森林，开始熟悉奔跑和跳跃 |
| 200–499 | 树影穿梭客 | 能在树影之间保持节奏，顺手带走沿路收获 |
| 500–999 | 灌木飞毛腿 | 跳跃越来越稳，已经能灵活穿过常见障碍 |
| 1000–1699 | 林间寻路家 | 熟悉小径变化，懂得在安全和收获之间做选择 |
| 1700–2499 | 风之探险家 | 跑得更远，能把森林里的节奏掌握在自己手里 |
| 2500 及以上 | 森林传说 | 这一趟表现出色，成为值得称赞的森林跑者 |

称号只表示本局表现，不代表闯关完成，也不增加角色数值或解锁新地图。六档门槛属于初始调参建议，应结合收集频率和实际游玩时长校准，争取让第一次游玩的玩家也能看到至少一次称号变化。

前两次升级间隔较短，让玩家容易获得反馈；后续档位间距逐步拉开，为较长的一局留下追求。称号统一按总囤粮分判定，时间分、松果分和蘑菇分均计入，不要求收齐某一种食物。分数一次跨过多个门槛时，直接更新到当前最高档，避免连续弹窗遮挡操作。

### 慢慢增加的难度

| 项目 | 初版建议 |
|---|---|
| 安全起步 | 前 6 秒不出现障碍，可先练习跳跃和收集 |
| 前期节奏 | 前 30 秒保持基础速度，提供足够时间建立操作信心 |
| 加速规则 | 从有效奔跑时间达到 30 秒起，每满 30 秒增加初始速度的约 4%，不按当前速度复利增长 |
| 速度上限 | 最多为初始速度的 1.25 倍，此后保持稳定 |
| 障碍间隔 | 连续两个障碍到达 Lita 所在位置之间至少间隔约 4 秒；加速后仍保持此时间空档 |
| 出现位置 | 从画面右侧清楚进入，初步争取至少约 2 秒的可见反应时间，不在脚下突然生成 |
| 食物布置 | 以安全可达的位置为主，不为了高分要求玩家跳进障碍 |
| 地形 | 固定平地、低矮障碍，不追加坑洞和头顶障碍 |

初始速度、跳跃高度、滞空时间、物品高度和碰撞范围需要一起试玩。目标是让新手经过简单说明后，有机会玩满约 1–3 分钟；这是调优目标，不是已验证结果。若试玩结束过快，优先降低初速、缩小有效碰撞范围或放宽空档，不靠增加操作数量提高门槛。

## 7. 五种页面状态

继续采用此前确认的五种页面，共用同一套森林背景，通过文字、按钮和面板切换表达不同状态。

| 页面 | 主要内容 | 操作与表现 |
|---|---|---|
| 主菜单 | 英文游戏名 Go Lita、待机 Lita、森林小径 | 主按钮“出发囤粮”，次按钮“怎么玩” |
| 玩法说明 | 自动奔跑、跳跃、障碍、两种食物和计分示意 | “出发囤粮”“返回”；不加入四方向移动说明 |
| 跑酷中 | 囤粮分、松果与蘑菇数量、右上角暂停按钮 | HUD 保持轻巧；六档称号出现后短暂淡出，不遮挡跑道 |
| 暂停菜单 | 浅色居中面板，提示“歇歇尾巴” | “继续跑”“重新出发”“回主菜单” |
| 游戏结束 | 提示“这一趟收获不错！”、本局囤粮分、食物数量、本局称号 | “再跑一趟”“回主菜单”；Lita 停下，不表现受伤 |

游戏结束文案不暗示已经收齐全部食物。持久化最高分在确认平台支持并完成验证后再补；MVP 先显示本局成绩，不依赖存档能力。

## 8. 美术方向与最小素材量

### 森林视觉

- 扁平卡通插图为主，整体比参考截图更明亮、轻盈。
- 用天蓝、云白、草绿、柔和青绿构成环境；用少量暖色突出 Lita 和食物。
- 背景采用大色块和少量层次，避免写实森林、厚重棕色顶栏、粗重立体按钮和密集纹理。
- Lita 保留默认角色的识别特征；森林、食物和障碍的线条与色块向现成角色靠拢，减少重新绘制角色的成本。
- 画面始终按横屏 4:3 构图。跑道、角色与障碍轮廓清楚，前景装饰避开碰撞区域。

### 最小资源清单

| 资源 | 最低需求 | 复用与新增原则 |
|---|---|---|
| Lita | 1 个角色资源，满足待机、跑动、跳跃、停止四种展示状态 | 优先复用默认角色；展示状态不等于必须新增四套动作素材 |
| 森林背景 | 1 张横屏 4:3 背景 | 优先查看平台或课程可用资源；已有俯视场景不能直接当成横版背景使用 |
| 地面 | 1 条平整、可重复地面 | 可用简洁色块和草地边线，不强制绘制复杂土层 |
| 障碍 | 小树桩、圆石、落枝堆各 1 种外观 | 共用一套生成、移动和碰撞逻辑；先做一种验证，再补另两种外观 |
| 松果 | 1 种外观 | 优先检查现成资源是否适合侧视和当前画风 |
| 安全蘑菇 | 1 种外观 | 与障碍有明显色彩、轮廓区分 |
| UI | 五种状态共用面板与按钮样式，配原生文字 | 若原生控件不满足布局，再补少量可复用无字按钮造型 |
| 音效 | 可后补跳跃、收集、受阻三个短音效 | 先完成无声可玩的版本；现成音效先确认可用性 |

按资源组计，共约 6 项：Lita、背景、地面、障碍组、松果、蘑菇。已有资源能覆盖多少，需要实际盘点；本稿不承诺全部现成。五个页面不分别制作五张场景图。

现有《游戏美术规划 v0.1》仍是设计师主题的历史方案。本版先确定 Lita 主题，后续应据此另行更新美术规划中的角色、障碍、收集物、页面文案和生图提示词。

## 9. XBuilder / XGo / SPX 实现条件

开发继续使用用户自己的 XBuilder 账号及现有 `IdeaDash` 项目。需要登录或验证时由用户操作。XBuilder 官方仓库仅作只读参考。

| 待核实事项 | 核实目的 |
|---|---|
| 舞台比例与资源尺寸 | 确认 4:3 舞台设置、实际像素尺寸及角色显示大小 |
| Lita 造型与动画 | 确认已有动作、朝向、切换方式，优先复用 |
| 地面、重力与跳跃 | 验证落地判断、单次起跳、滞空时间和碰撞区域 |
| 障碍与食物生成 | 确认可用的克隆或有限对象循环复用方式，及时回收离屏对象 |
| 计分与状态管理 | 区分主菜单、说明、运行、暂停、结束；只在运行时累计有效时间 |
| UI 与输入 | 验证按钮、文字显示和键鼠事件，避免菜单点击串入跳跃 |
| 暂停与重试 | 确认对象运动和所有计时可统一冻结、恢复及重置 |
| 项目导出与 GitHub 记录 | 确认导出能覆盖源代码、项目配置及运行所需素材，再安排阶段性归档 |

已有资料提供 XBuilder、XGo 和 SPX 的技术方向，但本稿不写入未经本项目验证的 API 签名或直接照搬其他引擎代码。Lita 编辑页和教程系列页本次能返回页面外壳，具体编辑器资源及课程界面内容尚未完成核查。

## 10. 实施顺序与首版验收

### 按最小工作量推进

1. 盘点 Lita、森林、松果和蘑菇资源，确认舞台、角色朝向与显示大小。
2. 用简化地面和一种障碍完成“开始 → 自动跑 → 跳跃 → 碰撞结束 → 重试”。
3. 加入松果、蘑菇、囤粮分和六档称号，再验证安全布置。
4. 补齐说明页、暂停菜单和结算信息，检查暂停及重置是否完整。
5. 试玩并调整初速、障碍间隔、跳跃和尾巴碰撞，再补其余障碍外观与森林细节。

### 首版完成标准

- Lita 在单一森林场景中连续跑动，输入能稳定触发一次跳跃。
- 障碍看得见、跳得过，食物能正常收集且每个目标只计分一次。
- 分数、食物数量和本局称号一致，暂停及结束状态不继续计时。
- 重试后对象、分数和速度干净重置，重复游玩不会不断积累离屏对象。
- 五种页面都能按预期切换，按钮不会误触发跳跃。
- 有效游玩时间越长，难度缓慢增加并最终封顶，试玩反馈支持轻松耐玩的方向。

MVP 不安排多地图、四方向自由移动、毒蘑菇判断、分类归篮、敌人战斗、河道、小船、在线排行榜或跨局库存。先把这一段森林跑酷做完整。

## 11. 与实际工作及比赛的联系

这款小游戏可以成为 Lita 新人教程之外的一次轻量作品展示：使用熟悉的角色和森林题材，把移动、事件、判断、计数、循环与状态等能力组织成一个能反复游玩的成品。

AI 参与规划、代码辅助、美术探索和问题排查，过程通过设计文档、提示词、代码变更和试玩记录体现。游戏故事围绕 Lita 的采集冒险展开，AI 元素不再作为游戏内道具，比赛目标通过真实的创作过程和成果表达。

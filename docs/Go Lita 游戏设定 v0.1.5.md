# Go Lita

> 一场为冬天多攒一点的小冒险：2D 横屏、4:3、单人森林收集跑酷
>
> 游戏设定 v0.1.5｜2026-10-25
>
> 本版以用户最新反馈为准：只按收获计分，增加左右控制、真实下落、随机地形与多种障碍。保留 v0.1.4 作为历史版本。

## 1. 定位与故事

冬天快到了，Lita 沿森林小径寻找食物和闪亮的森林宝藏。前方有平缓草地、悬浮草台，也有风吹断的小径和挡路的危险。玩家帮助 Lita 选择路线、调整位置、跳过障碍，把这一趟的收获带回家。

核心体验：**一边向前探索，一边选择值得冒险的收集路线；每一分都来自真正捡到的收获。**

| 项目 | 本版规则 |
|---|---|
| 游戏名称 | Go Lita；XBuilder 项目标识继续使用 IdeaDash |
| 主角 | 复用平台默认 Lita，保留 Idle、Walk、Jump、Fall 动画 |
| 场景 | 一套明亮扁平卡通森林，横屏 480 × 360，4:3 |
| 类型 | 自动向前推进的收集跑酷，支持左右调整与单次跳跃 |
| 目标 | 收集更多物品，刷新本局囤粮分与成长称号 |
| 前期体验 | 先练移动和跳跃，再遇见单独障碍，后续逐渐开放短缺口与草台组合 |
| 本轮界面范围 | 直接进入游戏，轻量 HUD、屏幕操作按钮、暂停与场内重试提示；独立开始页、介绍页和结算页继续留待后续 |

仍然承接 Lita 系列教程的“森林储藏计划”，不扩展为完整教程剧情。水晶属于森林宝藏，采用统一的“囤粮分”记录本次探索收获，并不把水晶解释为食物。

## 2. 本轮素材与游戏对象

| 对象 | 当前用途 | 规则 |
|---|---|---|
| Lita | 主角 | 身体与脚部参与碰撞，蓬松尾巴不作为危险判定范围；始终显示在场景精灵前面 |
| 草地 | 地面与悬浮平台 | 上表面可以站立；没有地面支撑时必须下落；悬浮平台可从下方穿过、从上方落稳 |
| 白云 | 装饰 | 缓慢移动，无碰撞、无分数 |
| 蘑菇 | 常见收获 | 每个 +1 分，安全、无毒 |
| 水晶 | 较少见的宝藏 | 每个 +3 分，通常引导跳跃或上层路线 |
| 火焰 | 已有危险 | 接触有效危险区域时结束本局 |
| 素材库补充障碍 | 丰富路况 | 优先从平台素材库选择易辨认的尖刺、石块或其他适合侧视的低矮危险；以实际选入的资源为准，在实现记录中列出 |

蘑菇暂代原方案中的松果，水晶保留现有外观。后续换美术不改变两档奖励结构，不需要重新设计积分系统。

## 3. 只按收获计分

### 明确公式

**囤粮分 = 蘑菇数量 × 1 + 水晶数量 × 3。**

- 取消存活时间分、奔跑距离分、跳跃次数分和躲避障碍分。
- 游戏运行但没有收集物品时，囤粮分保持不变。
- 每个物品只加分一次，领取后立即消失；离屏回收后，重新进入的新物品才能再次被领取。
- 结束、暂停及重试过程不允许继续收集加分。
- 漏捡不扣分，不设置连击倍率或逐秒衰减，避免分数难以理解。
- 重试把分数、两类收集数量和本局称号一起重置。
- 收集时提供短促的加分反馈；HUD 保持可读，不用持续弹窗遮挡路线。

例如，收集 5 个蘑菇、2 颗水晶，本局为 **11 分**。即使之后跑了 30 秒而没有收集，仍然为 11 分。

### 降低称号门槛

| 囤粮分 | 称号 | 反馈目标 |
|---:|---|---|
| 0–4 | 蹦跶小新手 | 刚出发，先熟悉操作 |
| 5–11 | 树影穿梭客 | 几次顺路收集就能获得首次成长 |
| 12–23 | 灌木飞毛腿 | 开始掌握跳跃和上下路线 |
| 24–39 | 林间寻路家 | 能稳定找到安全的收集路线 |
| 40–59 | 风之探险家 | 收获积累，愿意挑战更远的小径 |
| 60 及以上 | 森林传说 | 为较长一局留下目标 |

称号只按囤粮分判断，不按存活时间或某一种物品数量判断。一次跨过多个门槛时直接显示当前最高档。称号不增加数值能力，也不锁定地图。

## 4. 操作与角色状态

| 操作 | 作用 |
|---|---|
| ← / A，屏幕左箭头 | 向左调整位置并转向左侧 |
| → / D，屏幕右箭头 | 向右调整位置并转向右侧 |
| Space / ↑ / W，屏幕跳跃按钮 | 单次跳跃，落稳后可以再次起跳 |
| P / 屏幕暂停按钮 | 暂停或继续 |
| R / 屏幕重试按钮 | 重新出发 |

森林仍然向后滚动。没有方向输入时，Lita 在画面中的当前位置自动向前跑；左右输入用于在可玩区域中选位、追收获或避让。角色朝向遵循最近一次左右输入，不强制每帧转回右侧。

长按跳跃不自动连跳；短按也必须可靠识别。支持短暂离地宽限和落地前输入缓冲，减少“明明按了却没跳”的挫败感。按屏幕移动或暂停按钮不会串成一次跳跃。屏幕按钮区域位于底部，路线与物品避开按钮遮挡。

Lita 的代码放在自身精灵脚本内：负责输入、朝向、重力、落地、动画、身体碰撞与失败反馈。舞台只协调全局进度、地图生成、共享积分和重置。

## 5. 重力、落地和结束

- 每帧持续施加重力，不能再用固定高度作为永久隐形地板。
- 脚下有可站立草地时，脚底应贴住平台上表面；使用精灵可见脚部校准偏移，不能按整张带透明边缘的画布底部计算。
- 下降时穿过平台上表面才落地，避免从侧面或底部被吸上平台。
- 离开平台边缘后继续自由下落；只有短暂宽限时间可补跳，不能无限悬空。
- 掉出画面下边界，或接触明确的危险区域，结束本局。
- 结束立即停止地图运动、生成、难度计时与收集；场内显示失败原因和重试提示。
- 重试清空旧克隆、临时加分提示、方向状态、收获、地图序号和速度，再恢复安全起步。
- Lita 始终在平台、道具和装饰上方渲染，平台不能遮住角色。

采用统一的手动重力与平台表面碰撞也可以满足本版需要，避免同时启用两套重力。实现应以实际落地、走出边缘、跳过缺口的表现验收，而不是只设置一个“重力”开关。

## 6. 随机路段与难度

### 有约束的随机

一套森林背景内，通过不同路段模板、道具位置与障碍外观产生变化。路段只能从已校准可通过的组合中抽取，不逐个无约束散布障碍。

| 路段类型 | 体验 |
|---|---|
| 补给草地 | 长平台、少量蘑菇，给新手和上一段挑战留出恢复空间 |
| 低障碍小径 | 地面上单独一个低矮危险，前后有安全落脚点 |
| 上层宝藏 | 可选草台、水晶；主路尽量保留替代路线 |
| 短缺口 | 一跳可通过，缺口后提供足够长的平台，不在落点堆叠危险 |
| 高低交替 | 小幅平台高度变化，收集物提示跳跃方向 |

规则：

- 开局至少 8 秒不出现危险；前 20 秒不安排必须跨越的缺口。
- 前 30 秒保持较慢基础速度；此后每 30 秒增加初始速度约 4%，最多到 1.25 倍。
- 缺口宽度和平台高差由实际跳跃能力限制；前方至少保留可见预警，不在 Lita 脚下改变平台。
- 缺口前后不放危险，不连续排列两个必须精准操作的组合。
- 不同障碍使用同样清楚的危险语义，避免把装饰误认为可以踩的平台。
- 蘑菇以顺路、低风险位置为主，水晶引导可选跳跃。收集物不与障碍重叠，不为拿分诱导必死落点。
- 回收离屏路段、克隆和物品，长时间游戏不能无限累积对象。
- 随机种类与参数是制作目标，最终已实现的范围和实测限制写入游戏版本说明。

## 7. 代码组织与平台条件

| 位置 | 职责 |
|---|---|
| 舞台 main.spx | 状态、积分、称号、时间步、路段生成与回收协调 |
| Lita.spx | 控制、重力、平台落地、身体判定、动画、朝向、层级 |
| 草地等平台脚本 | 初始化、尺寸/坐标、滚动显示、可站立表面 |
| 蘑菇、水晶脚本 | 生成/显示、领取判定、单次加分、回收 |
| 危险精灵脚本 | 对应危险的外观、动画、碰撞和回收 |
| 云朵脚本 | 装饰视差循环 |
| 屏幕控制精灵 | 触屏/鼠标操作和重试、暂停输入 |

XBuilder 与 XGo/SPX 是实际运行环境，不能直接粘贴 Unity/C# 或 JavaScript 引擎代码。平台精灵存在舞台边缘位置限制时，应保留独立的逻辑坐标，避免回收与碰撞依赖被限制的绘制坐标。

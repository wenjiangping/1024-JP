# 高分运行稳定性修复

问题：障碍密度按档位递增，在 60 分后超过每段两个固定槽位；第五段写入第三个障碍时访问下标 10，造成运行失败。其他路段可能提前覆盖相邻数据。

方案：保留现有十个障碍槽位及每段两个障碍的排布，新增 `nextObstacleCount`，在累计配额前将实际密度封顶为 2；余数始终小于 1，不积压无法容纳的障碍。速度、低分配额、空档、缺口起落与双障碍间距继续使用现有规则。

验证：从正式源码提取函数执行 Go 回归，旧版应失败、新版应通过；检查 14 个分数、28 万次路段再生、6 万次配额分配。随后在 XBuilder SPX 3.3.0 中编译并用临时包检查高分路段再生、连续运行、结算及重试。临时分数不作为自然试玩成绩。

交付顺序：先提交 GitHub PR，再同步原项目 En/IdeaDash；备份云端原包，验证后恢复正式包，导出比对所有脚本并确认无测试入口，最后发布一次。对玩家的发布概述：修复游戏运行问题，提升游玩稳定性。

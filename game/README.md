# Go Lita runner v0.7

480 × 360、4:3 的单人森林收集跑酷。新增首页、游戏说明、动态结算、十档成就图片和用户提供的绿色按键；v0.7 的运行页使用 XBuilder 系统 Monitor，左右外边距保持一致；结算页恢复原版橙色数字和称号，读取结束瞬间冻结的 `FinalScore` / `FinalRank`；工程缩略图使用 `HomeCover`。最新玩法与机制统一维护在[仓库首页](../README.md)，旧设定仅供历史追溯。

## 打开与流程

云端：[En / IdeaDash，显示名 Go Lita](https://x.qiniu.com/editor/En/IdeaDash/stage/code)。点击“运行”后显示首页，点击 START 打开说明，再点击说明图片的任意位置开始游戏。说明关闭的点击不会穿透为跳跃。失败后显示本局实际囤粮分和对应称号；RESTART 直接重开，HOME 返回首页。首页、说明、结算均冻结地图和计分。首页与说明页循环播放背景音乐，进入跑酷后停止。

本地恢复：先导出需要保留的修改，再通过项目菜单导入 **Go-Lita-runner-v0.5.xbp**。包内包含全部源码、图片、动画及声音。仓库同时保留历史版本，当前正式包沿用 v0.5 文件名以保持导入路径稳定，源码已经是 v0.7 增强版。2026-11-03 已更新并发布到原项目 `En / IdeaDash`，发布内容与验证记录见 [PLAYTEST.md](PLAYTEST.md) 和 [PR #5](https://github.com/wenjiangping/1024-JP/pull/5)。

完整 XBuilder 云端存档见 [`archive/Go-Lita-XBuilder-IdeaDash-2026-10-26.xbp`](archive/Go-Lita-XBuilder-IdeaDash-2026-10-26.xbp)。该文件是从已发布的 `En / IdeaDash` 项目直接导出的完整包，包含工程源码、所有精灵与造型、动画、声音、背景、字体和配置；演示视频见 [`media/Video-Go-Lita.mp4`](../media/Video-Go-Lita.mp4)，在线体验见 [Go Lita](https://x.qiniu.com/project/En/IdeaDash)。

| 输入 | 操作 |
|---|---|
| ← / A，→ / D | 左右移动、转向；松开后森林继续推进 |
| Space / ↑ / W | 单次跳跃，长按不连跳 |

| Space | 首页进入说明，说明进入游戏 |

键盘事件配合按键状态采样；方向事件保留 12 帧脉冲。开始与重试清理残留输入。键盘输入仍需浏览器预览获得焦点，项目脚本无法跨窗口强制抢焦点。

本局结束时保留对应的失败提示；当前运行会话中的最高分会保留，但不再显示“新纪录！”气泡。重新开始不会清除会话最高分，刷新或重新打开项目后重新计数。运行页的系统 Monitor 绑定 `Score` 和 `Rank`；结算页从同一数据源冻结为 `FinalScore` 和 `FinalRank`，使用原版橙色数字与称号图片呈现。结束只冻结一次，后续重绘或输入不会改变本局结果。该反馈不改变囤粮分公式。

## 跑酷与物理

舞台开启 `physics: true`。Lita 为 Kinematic；地形、实体及危险障碍为 Static；云、收集物和 UI 为 None。代码处理循环地图、角色重力与碰撞，避免引擎重复施加重力。

- 石头、树桩、乱石堆、草地侧壁属于实体：侧面阻挡并推挤，顶部可落脚，接触不直接失败。
- 火焰、炸弹属于危险：身体进入有效区域即结束；尾巴不计入判定，炸弹播放已有 32 帧爆炸一次。
- 仅三种失败：危险接触、有效身体完全被挤过左边界、踩空后落出下边界。
- 重力 560、起跳速度 335，保留 0.11 秒离地宽限、0.12 秒输入缓冲和小高差衔接。Lita 位于世界上层，UI 在角色之上。
- 五个循环地形槽组合平地、实体、水晶路线、草台、炸弹、火焰、台阶和短缺口。运行页的分数和称号直接由系统 Monitor 读取舞台变量；结算页的数字克隆读取冻结积分。重试先清理再重建世界与数字克隆。

`ScoreMonitor`、`RankMonitor` 直接写入 `assets/index.json` 的系统控件区。结算页的系统 Monitor 已按后续要求移除，恢复原版文字样式。`main.spx` 只通过 `getWidget(Monitor, ...)` 与 `show` / `hide` 控制页面可见性，运行页不使用精灵模拟系统控件。`builder-thumbnail.jpeg` 由 `HomeCover` 的 artwork 生成，项目卡片和运行首页保持同一视觉来源。HomeCover 的编辑态默认可见，避免 XBuilder 自动生成缩略图时再次截到场景中的石堆。

## v0.6 完整度修复

路段生成完成后会检查本路段全部障碍槽与三个收集物的水平重叠。被障碍覆盖的收集物自动抬到跳跃路线，避免素材被遮挡或出现“看得见但无法安全拿到”的情况；有草台的路线仍优先使用草台高度。

## 高分运行稳定性修复背景（2026-11-05）

原生成器会在 60 分后分配 3 个、100 分后分配 3–4 个障碍，但每路段仅有两个槽位，可能覆盖相邻路段或越界。当时的修复将实际障碍密度封顶为 2 后再累计小数配额。本轮已经安全扩容到每段三个槽位，并仅在阶段 7–10 使用三障碍配额；当前规则以仓库首页为准。工程包路径沿用 v0.5 文件名。

本地生成器回归使用已安装的 Go，仅转换生产 XGo 函数的省略括号调用并添加观测，不重写生成算法：

```powershell
python game/tools/check_obstacle_capacity.py --work-dir D:\AAA-WORK\CodeX-other\go-lita-highscore-fix-20261105\temp
```

当前检查覆盖全部新门槛前后及 999 分，共 44 万次路段再生、11 万次配额分配，并逐阶段遍历全部 10 个模板验证危险物分布；检查槽位归属、数组范围、双/三障碍间距、缺口与开局安全路线。它是生成器测试，不等同于自然通关。

`create_highscore_playtest.py --output <明确的临时路径>` 生成带 `QACapacity` 标记的 XBuilder 临时包：1 检查 14 个分数下共 2800 次路段再生；2/3/4/5 分别从 70/80/100/126 分启动持续运行；6 结束并检查结算。临时包只跳过角色物理与危险事件，以便验证高分持续生成与渲染，保留正式计分、界面和地图逻辑。发布前必须恢复正式包；打包器会拒绝 `QACapacity`。

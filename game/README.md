# Go Lita runner v0.3

480 × 360、4:3 的单人森林收集跑酷。本版把障碍拆成**实体阻挡**与**危险接触**，增加乱石堆、炸弹和收集路线，并修正首次跳跃输入。规则对应 [文档 PR #2](https://github.com/wenjiangping/1024-JP/pull/2) 中的 v0.1.6。

## 打开与操作

云端：[En / IdeaDash，显示名 Go Lita](https://x.qiniu.com/editor/En/IdeaDash/stage/code)。已保存到原项目，点击“运行”试玩，无需发布。

本地恢复：先导出需要保留的当前修改，再通过项目菜单导入 **Go-Lita-runner-v0.3.xbp**。包内包含完整源码、背景、精灵、动画和声音。旧 v0.2 可从 Git 历史恢复。

| 输入 | 操作 |
|---|---|
| ← / A，→ / D | 左右移动并转向；松开后森林继续向左推进 |
| Space / ↑ / W | 单次跳跃，长按不连跳 |
| 底部左右箭头、上箭头 | 屏幕移动与跳跃 |
| 点击上部游戏区域 | 跳跃；底部按钮区域独立处理 |
| P / 暂停按钮 | 暂停、继续 |
| R / 回转箭头 | 清空本局并重试 |

保留积分、称号和底部操作按钮；删除原顶部 Hint/提示控件。暂停和结束信息通过角色气泡表达。本轮没有独立开始、介绍、结算界面。

## 规则

- **蘑菇 +1，水晶 +3**。分数恒等于 `Mushrooms + Diamonds * 3`；时间、距离、跳跃不加分。物品只领取一次，暂停和结束不收集。
- 称号在 5 / 12 / 24 / 40 / 60 分升级。
- **石头、树桩、乱石堆、草地侧壁**属于实体。侧面阻挡并随滚动向左推角色，接触不扣分、不立即结束；从上方可以落在实体顶部。
- **火焰、炸弹**属于危险。角色身体进入有效区域立即结束；尾巴不参与危险判定。炸弹平时显示默认造型，接触后播放已有 32 帧爆炸一次，立即冻结计分和地图；重试清理旧克隆与动画。
- 只有三种结束：危险接触、有效身体完全被推过左边界、失去支撑后身体落出下边界。
- 重力 560、起跳速度 335，跳跃高度约 100 像素。保留 0.11 秒离地宽限、0.12 秒输入缓冲。明显台阶及悬浮草台侧壁阻挡，最多 8 像素的小高差可平顺衔接；草台下保留至少 50 像素净空。
- 新局 `jumpHeld = false`，第一次有效输入不再因“已长按”状态被丢弃。云端重载后实测无需再点击画面即可使用第一下空格。
- Lita 每帧保持场景前层。朝向切换围绕身体进行，避免翻尾巴造成碰撞体突然横移。

## 路段与难度

五个循环地形槽组合十种模板：补给平地、单实体、悬浮草台、乱石水晶、短缺口、树桩加火焰、炸弹、草地台阶、双实体、草台与火焰分路。随机宽度、高度、对象种类和部分摆放位置；水晶在障碍上方或上层路线，蘑菇在安全路面。

初始三个路段为安全区，之后先练习实体障碍；连续两个挑战后安排补给路。危险在更后面出现，缺口限 36–48 像素、不连续，前后清除障碍。初速 58，每 30 秒增加初始值 4%，封顶 72.5；开局至少前 8 秒保留练习空间，前 20 秒没有必过缺口。

每个路段最多两个障碍，间距至少约 130 像素。固定池共 70 个克隆：5 个草台、15 个收集物、5 种障碍各 10 个；离屏循环槽位，重试先清理旧克隆。未做长时间内存仪表测试。

## 工程结构

| 路径 | 职责 |
|---|---|
| `Go-Lita-runner-v0.3.xbp` | 可导入的完整工程包 |
| `project/main.spx` | 状态、收集计分、称号、随机路段、重置与帧协调 |
| `project/Lita.spx` | 键鼠输入、重力、实体碰撞、动画、边界结束 |
| `project/石头.spx`、`树桩.spx`、`石头1.spx` | 各实体的显示和克隆池；共用几何与 Lita 的碰撞计算一致 |
| `project/火焰.spx`、`炸弹.spx` | 各自危险判定、显示和动画；炸弹不在普通 render 中重置爆炸 |
| `project/蘑菇.spx`、`水晶1.spx` | 物品判定、单次领取与隐藏 |
| `project/草地*.spx`、`草台.spx`、`白云*.spx` | 地形与装饰显示 |
| `project/Move*.spx`、`*Button.spx` | 各自屏幕按钮的事件和持续按压 |
| `project/assets/` | 全部图片、造型、32 帧炸弹动画及声音索引 |
| `tools/` | 打包、完整性校验及临时固定路段测试工具 |
| `PLAYTEST.md`、`evidence/` | 实测结果、日志、截图和未覆盖范围 |

手动重力与 SPX 内建物理不同时启用。模拟、碰撞和回收使用独立逻辑坐标，避免 SPX 绘制坐标被舞台边缘限制后无法结束。

## 检查与打包

只需 Python 3，无第三方依赖：

```powershell
python game/tools/package_project.py --check
python game/tools/package_project.py
```

第一条检查资源、动画帧、精灵及声音顺序、压缩包与源码逐字节一致；第二条在编辑 `project/` 后重建包。正式工程不允许混入 `QAScenario` 测试布局。资源检查不代替 XBuilder 的实际编译和试玩。

需要复现单项碰撞时：

```powershell
python game/tools/create_playtest_project.py
```

会在本任务根目录的 `other/` 子目录生成临时测试包，**不修改正式工程**。导入测试包后按 1–8，分别进入石头、树桩、乱石堆、火焰、炸弹、无支撑下落、28 像素台阶、悬浮草台布局；物品关闭，物理及危险脚本保持正式版本。第 6 项使用 90 像素缺口以稳定验证掉落，不代表正式随机缺口宽度。测试后恢复正式包。

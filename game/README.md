# Go Lita runner v0.7

480 × 360、4:3 的单人森林收集跑酷。新增首页、游戏说明、动态结算、五档成就图片和用户提供的绿色按键；v0.7 将运行页与结算页的囤粮分、称号统一改为 XBuilder 系统 Monitor，结算读取结束瞬间冻结的 `FinalScore`，并将工程缩略图换成 `HomeCover`。积分与难度对齐 [文档 PR #2](https://github.com/wenjiangping/1024-JP/pull/2) 中的游戏设定 v0.1.9。

## 打开与流程

云端：[En / IdeaDash，显示名 Go Lita](https://x.qiniu.com/editor/En/IdeaDash/stage/code)。点击“运行”后显示首页，点击 START 打开说明，再点击说明图片的任意位置开始游戏。说明关闭的点击不会穿透为跳跃。失败后显示本局实际囤粮分和对应称号；RESTART 直接重开，HOME 返回首页。首页、说明、结算均冻结地图和计分。首页与说明页循环播放背景音乐，进入跑酷后停止。

本地恢复：先导出需要保留的修改，再通过项目菜单导入 **Go-Lita-runner-v0.5.xbp**。包内包含全部源码、图片、动画及声音。仓库同时保留历史版本，当前正式包沿用 v0.5 文件名以保持导入路径稳定，源码已经是 v0.7 增强版。2026-11-03 已更新并发布到原项目 `En / IdeaDash`，发布内容与验证记录见 [PLAYTEST.md](PLAYTEST.md) 和 [PR #5](https://github.com/wenjiangping/1024-JP/pull/5)。

完整 XBuilder 云端存档见 [`archive/Go-Lita-XBuilder-IdeaDash-2026-10-26.xbp`](archive/Go-Lita-XBuilder-IdeaDash-2026-10-26.xbp)。该文件是从已发布的 `En / IdeaDash` 项目直接导出的完整包，包含工程源码、所有精灵与造型、动画、声音、背景、字体和配置；演示视频见 [`media/Video-Go-Lita.mp4`](../media/Video-Go-Lita.mp4)，在线体验见 [Go Lita](https://x.qiniu.com/project/En/IdeaDash)。

| 输入 | 操作 |
|---|---|
| ← / A，→ / D | 左右移动、转向；松开后森林继续推进 |
| Space / ↑ / W | 单次跳跃，长按不连跳 |
| 绿色左右键、上箭头 | 屏幕移动和跳跃 |
| 点击上部游戏区域 | 跳跃；底部按钮独立处理 |
| P / 暂停键 | 暂停、继续，成就计时同时冻结 |
| Esc | 暂停、继续 |
| R / 回转箭头 | 清空本局并重试，结算时也可用 R |
| Enter | 首页进入说明，说明进入游戏；结算页直接重开 |
| Space | 首页进入说明，说明进入游戏 |

键盘事件配合按键状态采样；方向事件保留 12 帧脉冲。开始与重试清理残留输入。键盘输入仍需浏览器预览获得焦点，项目脚本无法跨窗口强制抢焦点。

本局结束时 Lita 会给出对应的失败提示；当前运行会话中的最高分会保留，首次超过时显示“新纪录！”。重新开始不会清除会话最高分，刷新或重新打开项目后重新计数。运行页的系统 Monitor 绑定 `Score` 和 `Rank`，结算页绑定 `FinalScore` 和 `Rank`；`FinalScore` 在 `finishRun` 中只写入一次，因此结算页不会随重绘或后续输入变化。该反馈不改变囤粮分公式。

## 计分、称号与难度

蘑菇 +1、水晶 +3；`Score = Mushrooms + Diamonds × 3`。时间、距离、跳跃不加分，暂停和结束不收集，同一物品只领取一次。

| 阶段 | 囤粮分 | 称号 | 成就图 | 速度 px/s | 可布置路段目标障碍数 |
|---:|---|---|---|---:|---:|
| 0 | 0–19 | 蹦跶小新手 | 无 | 58 | 1.0 |
| 1 | 20–39 | 树影穿梭客 | 成就1 | 75.4 | 1.3 |
| 2 | 40–59 | 灌木飞毛腿 | 成就2 | 98.02 | 1.69 |
| 3 | 60–79 | 林间寻路家 | 成就3 | 127.426 | 2.197 |
| 4 | 80–99 | 风之探险家 | 成就4 | 165.6538 | 2.8561 |
| 5 | 100+ | 森林守护者 | 成就5 | 215.34994 | 3.71293 |

阶段统一为 `min(Score / 20, 5)`，速度每档乘 1.3，障碍生成密度在上一版基础上整体翻倍并继续按阶段乘 1.3，100 分以后封顶。每个路段最多两个障碍，安全路线规则仍会缓冲连续压力。障碍采用累计小数配额生成，每路段最多两个；开局、补给、缺口起落区域保留安全空间，短局实际障碍总数会受随机路线影响。新密度用于后续离屏生成的路段，不突然向当前画面添加障碍。

每局跨过 20 / 40 / 60 / 80 / 100 分时展示对应图片 1.6 秒，再淡出 0.35 秒。水晶跨档同样触发。HUD、成就和结算使用同一阶段表；失败或重开清除旧成就。

## 跑酷与物理

舞台开启 `physics: true`。Lita 为 Kinematic；地形、实体及危险障碍为 Static；云、收集物和 UI 为 None。代码处理循环地图、角色重力与碰撞，避免引擎重复施加重力。

- 石头、树桩、乱石堆、草地侧壁属于实体：侧面阻挡并推挤，顶部可落脚，接触不直接失败。
- 火焰、炸弹属于危险：身体进入有效区域即结束；尾巴不计入判定，炸弹播放已有 32 帧爆炸一次。
- 仅三种失败：危险接触、有效身体完全被挤过左边界、踩空后落出下边界。
- 重力 560、起跳速度 335，保留 0.11 秒离地宽限、0.12 秒输入缓冲和小高差衔接。Lita 位于世界上层，UI 在角色之上。
- 五个循环地形槽组合平地、实体、水晶路线、草台、炸弹、火焰、台阶和短缺口。固定世界克隆池外，分数和称号直接由系统 Monitor 读取舞台变量；重试先清理再重建世界克隆。

## 素材与布局

新增页面和操作键均来自用户提供的 `素材/` 原图，原文件不修改。`UI-ASSETS.json` 记录源图 SHA256、尺寸及工程路径。运行 PNG 等比例缩小以降低大图解码开销；囤粮分和称号使用系统 Monitor，不生成模拟控件图片。素材清单和运行资源随工程存档，无需原始大图即可导入运行。

按钮按本轮截图重新布局，替代上一版旧几何冻结规则。暂停后显示用户提供的“按键-暂停后开始”图标；不增加下蹲动作。

## 音频与资源清理

背景音乐仅在首页和说明页播放并按约 74 秒重新开始；跑酷与结算页静音。行走动画不再触发脚步声，失败只播放一次“坠落声”。危险炸弹已替换为“炸弹2”，爆炸使用其“动画2”。工程内移除未使用的旧炸弹与脚步声音频。

## v0.7 原生 HUD 与封面修复

`ScoreMonitor`、`RankMonitor`、`SettlementScoreMonitor` 和 `SettlementRankMonitor` 直接写入 `assets/index.json` 的系统控件区。`main.spx` 只通过 `getWidget(Monitor, ...)` 与 `show` / `hide` 控制页面可见性，不再用精灵模拟系统控件。`builder-thumbnail.jpeg` 由 `HomeCover` 的 artwork 生成，项目卡片和运行首页保持同一视觉来源。HomeCover 的编辑态默认可见，避免 XBuilder 自动生成缩略图时再次截到场景中的石堆。

## v0.6 完整度修复

路段生成完成后会检查两个障碍槽与三个收集物的水平重叠。被障碍覆盖的收集物自动抬到跳跃路线，避免素材被遮挡或出现“看得见但无法安全拿到”的情况；有草台的路线仍优先使用草台高度。

## 打包与复现

打包和完整性检查只用 Python 3 标准库：

```powershell
python game/tools/package_project.py
python game/tools/package_project.py --check
```

检查 4:3、全局物理、按钮几何、资源与动画、精灵和声音顺序、临时 QA 隔离、ZIP 完整性及源码逐字节一致。正式包为 33 个精灵、171 个文件和 4 个系统 Monitor；SPX 编译与预览需在 XBuilder 验证。

`python game/tools/create_native_hud_playtest.py --output D:\AAA-WORK\CodeX-other\go-lita-native-hud-20261103\temp\Go-Lita-native-hud-QA.xbp` 生成临时系统控件测试包，不改正式源码，输出路径必须显式指定。数字 1–5 实际调用收集函数跨过各阈值并验证重复收集；6/7 预置结算 126/0；8 测 18+3、重复水晶和暂停拒绝收集；9 结束为 21 分。6 还在结束后尝试收集和重复结束，并将实时分数改成 999，验证结算仍为 126。临时分数不是自然试玩成绩，测试后必须恢复正式包，禁止发布 QA 包。正式打包器会拒绝 `QAHUD` 标记。

`prepare_ui_assets.py --source 素材` 是可选的资源重建工具，需 Pillow 与 Windows 微软雅黑字体；已提交完整资源，无需重建即可运行。该工具会更新资源 ID，日常只改脚本不必运行。

`Parkour Game.zip` 仅为用户提供的参考，没有运行或搬用其 EXE/DLL、素材。官方 `goplus/builder` 仓库只读参考；本轮 PR #5 保持打开，未合并。

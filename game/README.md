# Go Lita runner v0.2

480 × 360、4:3 的单人森林收集跑酷。在已有项目中加入左右移动、真实重力、随机地形和三种危险，并改成只按实际收获计分。设计依据为 [设定文档 PR #2](https://github.com/wenjiangping/1024-JP/pull/2) 中的 v0.1.5。

## 打开与试玩

云端项目：[En / IdeaDash（显示名 Go Lita）](https://x.qiniu.com/editor/En/IdeaDash/stage/code)。本版已保存到该项目，重新加载后可直接运行。

需要恢复本地存档时，在 XBuilder 项目菜单选择“导入项目文件”，导入本目录的 **Go-Lita-runner-v0.2.xbp**，然后点击“运行”。导入会覆盖当前项目内容，应先导出需要保留的修改。运行预览无需发布。

| 输入 | 操作 |
|---|---|
| ← / A、→ / D | 左右移动并转向；松开后保持屏幕位置，森林继续滚动 |
| Space / ↑ / W | 单次跳跃，长按不连跳 |
| 底部左右箭头、向上箭头 | 鼠标/触屏移动、跳跃 |
| 点击游戏上部区域 | 跳跃；底部按钮区域独立处理 |
| P / 双竖线按钮 | 暂停、继续 |
| R / 回转箭头按钮 | 清空本局，重新出发 |

## 规则和体验

- 蘑菇 **+1**，水晶 **+3**。分数恒等于 `Mushrooms + Diamonds * 3`；时间、距离、跳跃和躲避均不加分。
- 称号在 5 / 12 / 24 / 40 / 60 分升级。暂停、结束不收集，重开清零。
- 重力持续作用，脚下必须有真实草地；下降落到平台表面才站稳。离开草台会掉向主路，走入缺口则可能掉出屏幕并结束。
- 相邻主路允许最多 16 像素的小台阶衔接，避免低地走向高地时穿透；空中不会被吸到高平台上。悬浮草台可从下方穿过。
- 使用脚部偏移校准落地；危险只检查身体，排除大尾巴。Lita 每帧位于场景精灵前层。
- 保留 0.11 秒离地宽限和 0.12 秒跳跃输入缓冲，减少边缘操作的挫败感。
- 随机组合补给平地、单个低障碍、空中水晶、悬浮草台、短缺口和小幅高低变化。平台宽度、草台高度、物品位置会变化。
- 开局有安全区，至少前 8 秒没有危险、前 20 秒没有必过缺口；实际出现时间随路段长度变化。缺口宽 36–48 像素，不连续生成，起落路段清除危险。
- 初始滚动速度 58；每 30 秒增加初始值的 4%，最高 72.5。缓慢增加的是速度，分数仍只来自收集。
- 使用五个循环路段、五个草台、十五个物品和十五个危险克隆。重开先销毁旧克隆，再创建固定数量。

本版直接进入游戏，保留轻量积分/称号/提示 HUD、暂停和场内重试；独立开始页、说明页、结算页继续留待后续。

## 可审阅的工程结构

| 文件 | 用途 |
|---|---|
| `Go-Lita-runner-v0.2.xbp` | 从实际试玩的 XBuilder 项目导出的完整包，含代码、配置、图片、动画和音效 |
| `project/main.spx` | 全局状态、纯收集计分、称号、路段生成、重置与帧协调 |
| `project/Lita.spx` | 方向、输入、重力、落地、动画和失败反馈 |
| `project/草地*.spx`、`project/草台.spx` | 主路和悬浮平台的显示与固定池 |
| `project/蘑菇.spx`、`project/水晶1.spx` | 各自物品的领取判断、单次奖励与隐藏 |
| `project/火焰.spx`、`project/石头.spx`、`project/树桩.spx` | 各类危险自己的身体碰撞和回收 |
| `project/白云*.spx` | 纯装饰视差 |
| `project/*Button.spx`、`project/Move*.spx` | 各自屏幕按钮的输入和区域判断 |
| `project/assets/` | 完整素材及资源索引；替换时保留精灵/动画名，并按新尺寸重新校准脚部和碰撞偏移 |
| `tools/package_project.py` | 检查资源完整性、包与源码一致性，或从工程重新打包 |
| `PLAYTEST.md`、`evidence/` | 验收结果与截图 |

精灵绘制坐标会受 SPX 舞台边缘限制，所以模拟、碰撞和回收使用独立逻辑坐标。手动平台重力与 SPX 内建物理不同时启用。

## 检查与重新打包

只需 Python 3，无第三方依赖。在仓库根目录运行：

```powershell
python game/tools/package_project.py --check
```

检查 22 个精灵、资源路径、动画帧、精灵顺序和压缩包中每个文件的内容。修改 `project/` 后运行以下命令重新打包，再导入 XBuilder 进行真实编译和试玩：

```powershell
python game/tools/package_project.py
```

资源检查不代替 XGo/SPX 编译。实际预览验证及本轮未覆盖项见 [PLAYTEST.md](PLAYTEST.md)。
